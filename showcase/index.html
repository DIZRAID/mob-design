Living style guide

Every token and every component, rendered by the real stylesheets.

This page links ../css/mob.css and ../css/a11y.css and paints nothing itself. If a swatch below is wrong, the token is wrong. If a control here looks different from the same control three sections down, the system has drifted — and that is what this page exists to catch. Class and token names are one-click selectable.

Semantic roles

The only tier a component is allowed to read. Redefining this block is how you retheme — flip the bar to Light and every value below re-resolves without a primitive moving. Contrast is measured live, and each readout names the ground it was measured against and the threshold that actually applies: 4.5:1 for text, 3:1 for a fill or a border that is the sole identifier of a control. The accent is measured the way it is used — as a fill with a white label on it, not as ink on a surface — which is the pair a11y.css says fails at 4.37:1. Turn on AA hardening and watch every flagged row clear its bar while the brand stays where it was.

Motion — live

Transform and opacity only, 80–260ms, no bounce, no overshoot. Press the button to run the scale; every dot travels the same distance so the only variable is time. The three easings run at --mob-duration-slow so their shapes are separable. Under prefers-reduced-motion, reset.css collapses all of it to 0.01ms — globally, with no component opt-out — so if your OS is set that way the dots will simply jump, and that is correct.

03

Button and icon button

components/button.css

How to read every state matrix on this page disabled, loading, selected and error are rendered by the system's own attributes — those cells are real. hover, focus and pressed are forced by the showcase, because a static page has one pointer and one focused element. The forcing rebinds the same published tokens the component's own rule reads and nothing else. Switch Simulate states off in the bar and hover the first cell in each row: if the live control does not match the forced one, something has drifted.

Variants × states

Four locals do all the painting — --mob-btn-bg, --mob-btn-fg, --mob-btn-border, --mob-btn-radius. Every variant and every state does nothing but reassign them, which is why no state can accidentally change geometry, and why the loading spinner picks up the current variant's colour without knowing which variant it is. Rest tones are muted by policy: saturation is spent on hover.

variant defaulthoverfocus presseddisabledloadingerror .mob-btn--primary .mob-btn--secondary .mob-btn--ghost .mob-btn--quiet .mob-btn--affirm .mob-btn--destroy .mob-btn--danger

A bare <button class="mob-btn"> is already the secondary treatment — the variant restates the default so it can be written explicitly. --destroy is the in-row destructive action, muted enough to repeat once per row without the table turning red; --danger is the loud one for a modal's confirm. Never swap them.

Sizes, selection and modifiers

Height, inline padding, radius and label size move together — a size step is one decision, not four. Selection is driven from ARIA, never from a class, and deliberately does not respond to hover: it is already the state.

Fields

components/field.css

One box, different contents

Input, textarea, select and search are not four components. Inside a .mob-input-wrap the control goes transparent, borderless and unpadded and the wrap paints the box — so a leading icon is a flex sibling of the text and can never overlap it, and nobody maintains a padding that happens to equal an icon width. The label persists after input, always: a placeholder disappears exactly when the user needs it.

Choice

components/choice.css

Checkbox, radio, toggle

Every control here is a real native input, made invisible but left in the document, plus a styled sibling that does the drawing. Tab order, Space, arrow-key group navigation, :indeterminate, form submission and every screen-reader announcement come free and cannot regress. A disabled checked control is deliberately not accent-filled: accent means live, and a dead control that still glows is exactly what the states matrix exists to prevent.

Overlays

Motion vocabulary

components/motion.css

.mob-enter is transition-driven, not animation-driven: open and closed are reversible mid-flight, so closing something halfway through its entrance turns it around from wherever it got to instead of restarting. The state lives in one attribute, so any framework drives it the same way, and an element with .mob-enter and no attribute is visible — server -rendered content is never invisible because the JS failed to load. Stagger caps at --mob-motion-stagger-max: a ten-thousand-row list reveals in a quarter of a second, and no row is ever unclickable because its turn has not come up.

Honest notes

what is not identical, and why

Where the reconstruction differs from Dashboard.dc.html

Every element of the prototype reproduced. Nothing had to be faked, approximated with a one-off class, or left out. Eight measurements differ, and all eight are the system choosing one value where the prototype had two — which is the whole point of a token layer, but it is still a difference and it is listed here rather than glossed over.

What Prototype System Δ Why
Chip surface #131417 / #141519 --mob-chip-bg 1 unit Two surfaces one unit apart for one component. chip.css calls it a prototype accident and collapses both.
Column-header title → chip 9px rail / 11px main 10px ±1px Same row, same job, two values. Normalised so repetition stays exact.
Pool block, mark → name 11px --mob-cluster-gap -1px Same normalisation, applied to the same 9/11 pair elsewhere in the file.

Three places the system deliberately overrides the prototype

The action stack is even

The prototype gave Claim and Close 8px of block padding and the "···" button 6px — roughly 32px against 28px. All three are one .mob-btn--sm here, so the stack is regular. Three buttons in one column at three heights is exactly the drift the size ladder exists to stop.

The 0.4% share survives

"In positions" is 4 parts in 1000 — under a pixel on the prototype's bar. --mob-bar-seg-min floors a real non-zero share at 2px, so the segment is visibly wider here. A series worth exactly zero is omitted from the markup instead, or the floor would draw a share that does not exist.

Keyboard focus exists

The prototype had no focus styling at all. Every control here ships a visible ring, every icon-only button has an accessible name, every mark has a text alternative, and the meter carries dir="ltr" so a numeric axis stays min → max when the page is mirrored.

What is simulated on this page, and what is real

Realrendered by the system
  • Every colour, size, radius, border and shadow — resolved live from the linked stylesheets. The values printed under each swatch are read back off the rendered element, not typed in.
  • disabled, loading, selected, current, invalid, error, indeterminate, dimmed and open/closed — all driven by the system's own attributes and pseudo-classes.
  • Theme, density, AA hardening and RTL — the four toggles write the same four attributes a product would write.
Simulatedand why it has to be
  • hover, pressed, focus. A document has one pointer and one focused element, so these three cannot all be shown at once. The showcase forces them by rebinding the same published tokens the component's own rule reads — never a new colour, never a new geometry. Switch Simulate states off and compare against the live control.
  • Fixed-position overlays. The modal, sheet, drawer and toast region are position: fixed. The dashed boxes around them create a containing block so they render in place instead of covering the page. In a product they are fixed to the viewport, and the backdrop is a real scrim.
  • This is a visual catalogue, not a working product. Buttons and product data demonstrate states; they do not save, trade, navigate or call a backend. For a small functional form with real client-side state, open the starter example.

What a reviewer should check

  1. Flip to Light. Every surface, border and status hue should re-resolve with the same hierarchy. Nothing should keep a dark value.
  2. Turn on AA hardening. Exactly four tokens change, and every contrast readout in Foundations that was flagged should clear 4.5:1. The brand should not visibly move.
  3. Turn on RTL. Every row mirrors; the meter axis and the sparkline do not, because they are numeric.
  4. Change density. Rhythm and card padding move. Control geometry, radius and colour must not — the M button is the same button in all three zones.
  5. Turn Simulate states off and hover the first cell of every matrix row. A forced cell that does not match the live one is drift.
  6. Narrow to 375px. Nothing may scroll the page sideways; wide content scrolls inside its own box.
  7. Tab from the top. Every control must show a ring, and the ring must follow the shape of the control it is on.

Coverage

This page renders the broad component vocabulary in realistic combinations. A few classes require a real scroll container, anchor or trigger to demonstrate honestly; their behaviour is documented next to the owning CSS instead of being faked here.
